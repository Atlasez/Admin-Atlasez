# カレンダー

- **目的:** 月を移動した際に古い応答が破棄され、次月の失敗から再試行できることを確認する。
- **画面:** /admin/calendar/
- **起動:** npm run agent:verify -- run calendar
- **Fixture:** admin-calendar.spec.tsのローカルルートFixtureが月ごとの予定を返し、指定リクエストを遅延・失敗させる。
- **操作:** カレンダーを開いて表示月を移動する。前月の応答を遅らせたまま次月の取得を失敗させ、再試行する。
- **成功条件:** 遅い前月の応答が表示月を戻さず、再試行後に次月の予定が表示される。
- **失敗条件:** 古い予定で上書きされる、読み込み状態から復帰しない、タイムゾーンの表示がFixtureと異なる。
- **状態検査:** リクエスト対象月、再試行回数、表示月の予定DOMを照合する。カレンダーサービスへの書き込みはない。
- **証拠:** JSONレポート、Console Error添付、外部origin遮断一覧。失敗時はスクリーンショットとTrace。
- **再現テスト:** tests/e2e/admin-calendar.spec.ts の「月移動の古い応答を破棄し、次の月の読込失敗を再試行できる」。
